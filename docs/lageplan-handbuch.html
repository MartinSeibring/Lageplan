1. Executive Summary

Lageplan ist ein integriertes strategisches Steuerungstool für die Energiewirtschaft, das vier Managementdisziplinen in einem einzigen Browser-Interface zusammenführt:

  • Strategische Umfeldbeobachtung über einen interaktiven Themenradar
  • Projekt- & Meilensteinplanung mit GANTT-Darstellung und Deadline-Tracking
  • Forschungs- & Innovationscontrolling als strukturiertes Projektregister
  • Risikomanagement mit quantitativem Risikoscoring und Cluster-Analyse

Das Besondere: Die vier Bereiche sind inhaltlich verknüpft — ein Thema aus dem Radar kann direkt zum Meilenstein werden, ein Meilenstein kann ein Risiko ableiten. Alle Daten werden per GitHub-Synchronisation geräteübergreifend geteilt und versioniert. Die Anwendung benötigt keinen Server, keinen Login, keine Installation — sie läuft direkt im Browser.

Besonderes Merkmal: Die gesamte Anwendung besteht aus einer einzigen HTML-Datei (~425 KB). Kein Build-Schritt, kein Deployment-Server, keine Datenbank — nur ein Browser und optional ein GitHub-Account.

3. GitHub-Synchronisation

Konzept

Jeder Nutzer hat seinen eigenen Browser-Cache (localStorage). Änderungen werden asynchron mit einer zentralen JSON-Datei auf GitHub abgeglichen. GitHub dient als versionierte Datenschicht — kein Datenbankserver notwendig.

Konfiguration (Einstellungs-Panel)

FeldStandardBeschreibung

BranchmainDatenbranch (je nach Umgebung vorbelegt)
Dateipfaddata/meilensteine.jsonPrimärer Dateipfad (Meilensteine)

Datendateien auf GitHub

DateiInhaltZuständiges Modul

data/themen.jsonThemenradar-EinträgeTR / GH

data/risiken.jsonRisikenRM / GH

Sync-Logik

Laden (kein PAT notwendig):

  1. JSON von GitHub laden (via raw.githubusercontent.com)
  2. Mit lokalem Cache zusammenführen: GitHub-Daten als Basis, lokal neue Einträge werden ergänzt
  3. Duplikat-Warnung bei identischem Titel + Deadline

Speichern (PAT notwendig):

  1. Aktuellen SHA der Datei von GitHub abrufen
  2. Daten als Base64-encodiertes JSON per PUT-Request schreiben
  3. Bei SHA-Konflikt (409 Conflict): Automatischer Retry nach 1 Sekunde
Debouncing: Jede Änderung wartet 2 Sekunden, bevor der Sync-Request ausgeht — verhindert unnötige API-Aufrufe bei schnellen Eingaben.

Zweck

Visualisierung des strategischen Umfelds: Welche externen Entwicklungen (regulatorisch, marktlich, technologisch, wettbewerblich) sind relevant und wie dringend?

Radar-Koordinatensystem

Die Visualisierung ist ein Polarkoordinaten-Diagramm (D3.js SVG) mit 4 Quadranten (Kategorien) und 3 Ringen (Zeithorizonte):

Kurzfristig100 px (innen)0–1 Jahr
Mittelfristig200 px (mitte)1–3 Jahre

FeldTypBeschreibung

Radar-Score-Formel

Zeitgewicht × 0,6 + (Auswirkung / 5) × 0,4 Zeitgewicht: kurzfristig = 1,0 · mittelfristig = 0,6 · langfristig = 0,3 Beispiel: kurzfristig, Auswirkung 5 → 1,0 × 0,6 + 1,0 × 0,4 = 1,0 (Maximum) langfristig, Auswirkung 2 → 0,3 × 0,6 + 0,4 × 0,4 = 0,34
ScoreAmpelfarbeBedeutungBadge
≥ 0,7RotKritisch — sofortiger HandlungsbedarfKritisch
≥ 0,5OrangeRelevant — auf dem Radar behaltenRelevant
< 0,5GrünBeobachten — kein unmittelbarer HandlungsbedarfBeobachten

Blip-Darstellung

  • Größe: Auswirkung × 3 → Radius 3–15 px
  • Deckkraft: 1 − (Unsicherheit − 1) × 0,15 (hohe Unsicherheit = transparenter)
  • Beschriftung: Nur bei Auswirkung ≥ 3, kollisionsgeprüft (überlappende Labels werden ausgeblendet)
  • Verteilung: Mehrere Einträge der gleichen Kategorie+Zeithorizont-Gruppe werden gleichmäßig auf einem ±40°-Bogen verteilt (alphabetisch sortiert, keine Überlappung)

Interaktive Funktionen

Tooltip (Hover über Blip)

  • Kategorie-Badge, Radar-Score (farbcodiert), Titel, Zeithorizont
  • Auswirkung als Sterne (★★★★☆), Cluster-Badges, anklickbarer Quellenlink
  • Tooltip bleibt offen wenn Maus hinüber bewegt (Linkklick möglich)

Detail-Panel (Klick auf Blip)

  • Vollständige Anzeige aller Felder
  • Beschreibung mit „mehr anzeigen ▾" bei > 120 Zeichen
  • Verlinkter Meilenstein: Liste verknüpfter Meilensteine mit Status-Badge und Fortschrittsbalken
  • „+ Meilenstein ableiten": Öffnet Meilenstein-Formular mit vorausgefüllter Thema-Verknüpfung
  • Bearbeiten / Löschen-Buttons

Filterung

  • Cluster-Filter: Mehrfachauswahl (kein Filter = alle sichtbar)
  • Freitextsuche: Titel, Beschreibung, Tags
  • Gefilterte Blips: Deckkraft 0,15 (ausgegraut), aktive: voll sichtbar
  • Kollisionsprüfung der Labels nach jedem Filterupdate

PESTEL-Analyse (unterer Bereich)

10. Themendurchgängigkeit — Wie Inhalte die Module verbinden

Das zentrale Designprinzip: Jede Information entsteht einmal und fließt durch alle relevanten Module. Kein Wechsel zwischen verschiedenen Tools notwendig.

Strategische Cluster als gemeinsames Rückgrat

Alle Module verwenden dieselben 5 strategischen Cluster als übergreifendes Ordnungssystem:

Netzanschluss  ·  Messstellenbetrieb  ·  Netzwirtschaft  ·  Technologie  ·  Organisation

Jeder Eintrag (Thema, Meilenstein, Risiko, Forschungsprojekt) ist einem oder mehreren Clustern zugeordnet. Das ermöglicht Filterung und Aggregation über alle Modulgrenzen hinweg — ein Stichwort wie „Netzanschluss" verbindet Themen, Meilensteine und Risiken desselben inhaltlichen Bereichs.
